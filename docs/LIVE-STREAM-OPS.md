# LIVE STREAM 配信メモ運用ルール

LIVE STREAM の配信メモは、担当するAIや更新回が変わっても、同じ読みやすさ・同じ公開範囲・同じ見た目になることを優先する。この文書を配信メモの共通ルールとし、サイト全体の安全基準は `AGENTS.md`、日々の掲載判断は `docs/CONTENT-OPS.md` に従う。

## 触る場所

- 配信メモのデータは `src/data/streamRecaps.ts` にだけ追加・更新する。
- 表示は `src/ActivitiesPage.tsx` の共通カードを使う。配信回ごとの専用レイアウトや専用見出しは作らない。
- 配信メモの内容を NEWS、Gallery、`media.ts`、`galleryVideos.ts`、STORY、予定へ自動転記しない。
- 配列は新しい配信を先頭に置く。同じ日付でも、確認できた時刻の新しい順にする。

## 1件の共通構造

`StreamRecap` は次の情報を同じ順番で持つ。

1. 日付・プラットフォーム・配信時間
2. 配信テーマ
3. 1〜2文の要約
4. 確認済みの代表静止画（`image`）
5. 代表の見どころ3件
6. 詳細内の追加情報

詳細には、必要な場合だけ次の順で置く。

1. 追加の見どころ（代表3件を除く）
2. 承認済みスクショと保存導線
3. 配信時点の目標
4. 個人名を伏せたランキング記録
5. タイムスタンプと次枠
6. 出典・確認日・公開範囲の注記

一覧では全カードを閉じた状態にする。どのカードも代表静止画と見どころ3件までを同じプレビューとして表示し、詳細を開いたときだけ追加情報を表示する。見どころ全体は3〜8件までとし、4件目以降は詳細へ置く。

## 入力の目安

- `summary` は短い要約にする。視聴していない内容や推測を足さない。
- 見どころは確認できた時刻、短いタイトル、事実ベースの本文をセットにする。時刻順に並べる。
- `goals` は配信時点の記録として0〜5件。プロフィールの固定情報へ移さない。
- `ranking` は個人名、順位表、他出場者の情報を公開しない。安全に一般化できない場合は、読み上げた事実だけを一文で残す。
- `timeline` と `nextNote` は確認できた範囲だけを記録する。未確認の予定を `streamSchedule` や `events` に追加しない。
- `sourceLabel` と `verifiedAt` は必須。Driveのフォルダ名、ファイルID、非公開URLはtracked textへ保存しない。
- `image` と `gallery` はオーナー承認済みのローカル素材だけを使う。画像にコメント、視聴者のアイコン、他出場者の表示が入る場合は掲載しない。

## やらないこと

- 配信ごとにハイライトの見出し・カード構造・ボタン文言を変える。
- 全文文字起こし、録音、画面録画、視聴者名やコメントを公開する。
- 配信中の数字をプロフィールや恒久的な実績へ転記する。
- 外部SNSの画像CDNや一時URLを新たな出典・メディアとして保存する。
- 「たぶん」「おそらく」などで不足情報を補う。確認できない項目は省略する。

## AIの提出前チェック

- `src/data/streamRecaps.ts` に必要項目が揃っている。
- 新しい回が先頭で、日付・時刻順が崩れていない。
- プレビューは代表静止画と見どころ3件で、追加情報は詳細内に収まっている。
- 本人・オーナーが確認した事実だけで、個人名や非公開情報を含めていない。
- NEWS、Gallery、予定など別のデータ面に不要な変更をしていない。
- `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm guard`、`git diff --check` を通してからPRにする。
